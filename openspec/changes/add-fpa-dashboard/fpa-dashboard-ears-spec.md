# EARS Specification: FP&A Dashboard for AI Usage (coffe)

**Version:** 3. Version 2 added the executive summary, tokens and cache, usage patterns, concurrency and lifecycle, subscription economics, and data-quality requirements. Version 3 adds UX, navigation, and call-to-action requirements (section 14).
**System name:** the Dashboard.
**Data source:** `data/usage_report_v3.json` (plus the extensions in section 2).

Requirement IDs are stable identifiers, not positions. IDs added in version 2 use ranges that follow the section they belong to, so some sections appear out of numeric order.

## Definitions

- **Effective cost:** API-equivalent pay-per-token estimate.
- **Cash cost:** subscription charges plus actual pay-per-token charges.
- **Leverage:** effective cost ÷ cash cost.
- **Full-month equivalent (FME):** a partial month's value × days_in_month ÷ days_elapsed.
- **Period:** the user-selected month range.
- **Prior period:** the same-length range immediately before it.
- **Interaction:** one event counted by the tracker. The exact definition is to be confirmed and documented (see FPA-140).
- **Premium model:** a model on a configurable list (default: Opus).
- **Dormant project:** a project with no activity for a configurable number of days (default 30).
- **View:** one of the top-level content areas: Summary, Cost, Breakdown, Habits, Outlook.
- **Primary CTA:** the single visually dominant call to action in a view. A **secondary CTA** is any other call to action, shown with less emphasis.

## 1. General

- **FPA-001** The Dashboard shall be generated by a stdlib-only Python script (`scripts/viz-fpa.py`) as a single self-contained HTML file with inline SVG.
- **FPA-002** The Dashboard shall show effective cost and cash cost as separate measures and never sum them.
- **FPA-003** The Dashboard shall label every figure with a provenance tag: *reported* (from the JSON) or *assumed* (from configuration).
- **FPA-004** When the report's last date falls before the end of its month, the Dashboard shall mark that month as partial and show the elapsed days out of the month's total.
- **FPA-005** The Dashboard shall show the report generation date and the tracker version in its header.
- **FPA-006** If the JSON fails schema validation, the generator shall exit with a non-zero status and list the failing fields.
- **FPA-007** The Dashboard shall open with an executive summary of three to five headline figures (effective cost, cash cost, leverage, cost per 1k interactions, and one outcome metric where available), each followed by a one-line interpretation derived from the data.
- **FPA-008** If a headline figure cannot be computed, then the Dashboard shall show "n/a" with the reason and shall not render an empty summary.
- **FPA-009** The Dashboard shall display a narrative claim (for example "cost under control" or "record multitasking") only when it is computed from a named metric and a threshold, both shown next to the claim.

## 2. Data requirements

- **FPA-010** The Dashboard shall consume monthly interactions, effective cost, sessions, autonomous-session share, and multitasking share from the report.
- **FPA-011** The tracker shall emit a monthly breakdown by tool and model (interactions and effective cost).
- **FPA-012** The tracker shall emit project totals per month, using `project_daily`.
- **FPA-013** The tracker shall emit actual pay-per-token charges separately from subscription charges.
- **FPA-014** Where a GitHub token is configured, the tracker shall emit commits and releases per project per month.
- **FPA-015** The Dashboard shall read the subscription schedule from configuration, with dated entries. The default schedule is Pro from Mar 19, Max from Apr 19, Pro from Jun 19.
- **FPA-016** The Dashboard shall read model pricing from configuration, versioned by effective date.
- **FPA-017** While no data exists for a month (Jan 1–10 has no logs), the Dashboard shall exclude that period from trend and unit-cost calculations and show an "n/a" marker.
- **FPA-018** The Dashboard shall read the project taxonomy (category → project) from a configuration file, and it shall place unmapped projects under "Unclassified."
- **FPA-019** The tracker shall emit input, output, cache-read, and cache-write tokens per month per model.

## 3. Hierarchies

- **FPA-020** The Dashboard shall provide three expandable trees: Time (Year → Quarter → Month), Tool (Tool → Model), and Portfolio (Category → Project).
- **FPA-021** Where the Portfolio tree has project-by-model data, the Dashboard shall allow drilling from Project into Model.
- **FPA-022** When the user expands a node, the Dashboard shall show its children with the same columns as the parent.
- **FPA-023** The Dashboard shall show the following columns in each tree: cost, % of total, interactions, cost per 1k interactions, and change vs prior period.
- **FPA-024** The Time tree shall additionally show budget, variance ($), and variance (%).
- **FPA-025** The Dashboard shall ensure every parent equals the sum of its children within $0.01 and one interaction.
- **FPA-026** When the user selects a period, the Tool tree and the KPIs shall recompute for that period.
- **FPA-027** While project-by-month data is unavailable, the Portfolio tree shall be limited to the full report period and show that limitation.
- **FPA-028** The Dashboard shall show a Pareto view of project cost with cumulative share, grouping the long tail into one row.

## 4. KPIs

The KPI strip shall compute each KPI for the selected period, and each KPI card shall show a monthly sparkline and a change vs prior period.

- **FPA-030** Effective cost, and the change in daily rate vs the prior period.
- **FPA-031** Cash cost, and the change in daily rate vs the prior period.
- **FPA-032** Leverage.
- **FPA-033** Effective cost per 1k interactions (lower is favorable).
- **FPA-034** Cash cost per 1k interactions (lower is favorable).
- **FPA-035** Effective cost per session (lower is favorable).
- **FPA-036** Top-3 project concentration, as a % of effective cost.
- **FPA-037** Premium-model share of effective cost, using a configurable list of premium models (default: Opus).
- **FPA-038** Autonomous-session share, weighted by sessions.
- **FPA-039** Multitasking: % of active hours with two or more projects, weighted by interactions.
- **FPA-040** Where outcome data exists, the Dashboard shall also show effective cost per commit and cost per release.
- **FPA-041** When the period includes a partial month, the Dashboard shall compare totals as daily rates, not as raw sums.
- **FPA-042** If a KPI's denominator is zero, the Dashboard shall display "n/a" and not zero or infinity.
- **FPA-043** The Dashboard shall show cache-hit rate, calculated as cache-read tokens ÷ (input + cache-read + cache-write tokens).
- **FPA-044** The Dashboard shall show the output-to-input token ratio.
- **FPA-045** If token data is unavailable for a tool, then the Dashboard shall mark the token KPIs as "n/a" for that tool, exclude it from the calculation, and show the excluded share.

## 5. Budget and variance

- **FPA-050** The Dashboard shall accept a monthly cash budget, a monthly effective-cost budget, and a target cost per 1k interactions.
- **FPA-051** The Dashboard shall apply budgets only from a configurable start month (default April).
- **FPA-052** When a month is partial, the Dashboard shall pro-rate its budget by elapsed days ÷ days in month.
- **FPA-053** The Dashboard shall calculate variance as actual minus budget and show the sign so that positive means over budget.
- **FPA-054** The Dashboard shall show a variance below budget as favorable and a variance above budget as unfavorable, using color and a text or symbol marker, not color alone.
- **FPA-055** The Dashboard shall show a variance table by month with actual, budget, variance ($), and variance (%) for both cost measures, plus year-to-date totals.
- **FPA-056** When the user edits a budget input, the Dashboard shall recalculate all variances without a page reload.

## 6. Bridge (price-volume-mix)

- **FPA-060** The Dashboard shall show a waterfall from the prior month's effective cost to the selected month's, split into Volume, Mix, and Rate.
- **FPA-061** The Dashboard shall calculate Volume as (Q1 − Q0) × prior average rate, where Q is total interactions.
- **FPA-062** The Dashboard shall calculate Mix as Σ(q1ᵢ × p0ᵢ) − Q1 × prior average rate, over models.
- **FPA-063** The Dashboard shall calculate Rate as Σ q1ᵢ × (p1ᵢ − p0ᵢ).
- **FPA-064** If a model has no prior-month interactions, the Dashboard shall use its current rate as its prior rate, so the model contributes to Mix only.
- **FPA-065** The Dashboard shall ensure Volume + Mix + Rate equals the cost change within $0.01.
- **FPA-066** When the selected or prior month is partial, the Dashboard shall use FME values and label the bridge accordingly.
- **FPA-067** While the change is small relative to the totals, the Dashboard shall truncate the y-axis and label it as truncated.
- **FPA-068** The Dashboard shall show a 100% stacked model-mix chart by month, in cost share.

## 7. Forecast and scenarios

- **FPA-070** The Dashboard shall project Oct–Dec (or the rest of the year) from a base run-rate, defined as the mean FME of the last three months.
- **FPA-071** The Dashboard shall accept scenario inputs: monthly volume growth %, rate change %, and the subscription plan for future months.
- **FPA-072** The Dashboard shall calculate forecast effective cost as base interactions × (1 + growth)ⁿ × base rate × (1 + rate change).
- **FPA-073** The Dashboard shall calculate forecast cash cost as the planned subscription price plus pay-per-token charges scaled by forecast volume.
- **FPA-074** The Dashboard shall show a year-to-date actual plus outlook total against the budget, with variance.
- **FPA-075** When the current month is partial, the Dashboard shall show the remainder of that month as a separate forecast row.
- **FPA-076** The Dashboard shall visually distinguish actual from forecast values in charts and tables, using a pattern or label and not color alone.
- **FPA-077** When the user changes a scenario input, the Dashboard shall update the forecast without a page reload.

## 8. Alerts

- **FPA-080** The Dashboard shall show a list of alerts, each with a severity, a rule name, and the evidence values.
- **FPA-081** If a month's Claude effective cost divided by that month's Claude subscription price exceeds a threshold (default 25×), then the Dashboard shall raise a "verify plan dates or other paid accounts" alert.
- **FPA-082** If the reported real cost differs from the subscription schedule's implied charges by more than a tolerance, then the Dashboard shall raise a reconciliation alert showing both figures. The README's $65.58 real cost vs. the ~$220 implied by June 10 is the motivating case.
- **FPA-083** If a month exceeds the effective-cost or cash budget, then the Dashboard shall raise a budget alert with the overage amount.
- **FPA-084** If cost per 1k interactions rises more than a threshold (default 15%) month over month, then the Dashboard shall raise a unit-cost alert.
- **FPA-085** If the premium-model cost share rises by more than a threshold (default 5 points) over three months, then the Dashboard shall raise a mix alert.
- **FPA-086** If the top-3 project concentration exceeds a threshold (default 50%), then the Dashboard shall raise a concentration alert.
- **FPA-087** If the report is older than a threshold (default 14 days), then the Dashboard shall raise a staleness alert.
- **FPA-088** The Dashboard shall make all alert thresholds configurable.

## 9. Interaction and presentation

- **FPA-090** The Dashboard shall offer period presets (YTD, Q1, Q2, Q3) and a custom month range.
- **FPA-091** The Dashboard shall provide navigation to the views Summary, Cost, Breakdown, Habits, and Outlook, and to the Data & method section (see section 14).
- **FPA-092** While the viewport is narrower than 600 px, the Dashboard shall use a single-column layout and put wide tables in horizontally scrollable containers.
- **FPA-093** The Dashboard shall support light and dark themes, following the system setting by default.
- **FPA-094** The Dashboard shall make all interactive controls keyboard-operable with a visible focus state.
- **FPA-095** The Dashboard shall format currency in USD and numbers with thousands separators, and use tabular numerals in tables.
- **FPA-096** The Dashboard shall include a Data section listing each metric, its source, its provenance tag, and its known gaps.
- **FPA-097** Where the browser blocks storage, the Dashboard shall still work and use default inputs.
- **FPA-098** Where repository creation dates are available, the Dashboard shall overlay them as markers on the monthly trend chart.

## 10. Usage patterns (retained from the current dashboard, extended)

- **FPA-110** The Dashboard shall show a day-of-week × hour heatmap of interactions in the configured timezone, labeled with that timezone.
- **FPA-111** The Dashboard shall show the after-hours share and weekend share of interactions, using configurable working hours (default Mon–Fri 09:00–18:00).
- **FPA-112** The Dashboard shall show week-over-week change in interactions and effective cost, and the variance of weekly values across the period.
- **FPA-113** The Dashboard shall show the most-used skills by number of uses.
- **FPA-114** Where the tracker emits the list of installed skills, the Dashboard shall list skills with zero uses, skills used exactly once, and each skill's monthly usage trend.
- **FPA-115** The Dashboard shall show the most-executed slash commands with their monthly trend.
- **FPA-116** The Dashboard shall show the distribution of session lengths in the buckets 1–10, 11–50, 51–100, and 100+ turns, and list the longest sessions with turns, cost, and project.
- **FPA-117** The Dashboard shall show effective cost by session-length bucket, plus the median and 90th-percentile cost per session.
- **FPA-118** The Dashboard shall show `/clear` executions per 100 sessions by month, and the count of sessions above a length threshold (default 100 turns) that contain no `/clear`.
- **FPA-119** The Dashboard shall show the first and last activity per tool and per model, and flag gaps longer than a configurable number of days (default 7).

## 11. Concurrency, autonomy, and lifecycle

- **FPA-120** The tracker shall emit, and the Dashboard shall report separately, (a) distinct projects per hour, (b) peak simultaneous sessions or agents, and (c) project switches per active hour. The Dashboard shall label (a) and (b) as parallel-agent measures and (c) as human context switching.
- **FPA-121** The Dashboard shall show a monthly trend of the share of sessions that use an Agent.
- **FPA-122** The Dashboard shall classify each project as new (first activity within a configurable number of days, default 30), active, or dormant.
- **FPA-123** The Dashboard shall show the number of active projects by month and the effective cost attributed to dormant projects, in total and per project.

## 12. Subscription economics

- **FPA-130** The Dashboard shall calculate utilization for each plan period as Claude effective cost ÷ plan price.
- **FPA-131** The Dashboard shall calculate, for each plan, the break-even monthly consumption (the effective cost at which the subscription equals pay-per-token, which is the plan price) and the headroom above it.
- **FPA-132** The Dashboard shall compare cash cost for the selected period under four cases: the actual schedule, all pay-per-token, all Pro, and all Max.
- **FPA-133** The Dashboard shall state that effective-cost equivalence ignores plan usage limits, so a plan may not be able to deliver the consumption shown.

## 13. Data quality and documentation

- **FPA-140** The Dashboard shall define "interaction" in the Data section. The tracker shall emit interactions by kind (user prompts, assistant turns, tool calls), and the Dashboard shall show the tool-call share so that inflation by agent activity is visible.
- **FPA-141** The tracker shall emit interactions and effective cost for the projects excluded by the charly filter, and the Dashboard shall show the filtered share of the total.
- **FPA-142** The tracker shall record the timezone used for hourly and daily bucketing, and the Dashboard shall display it. If the timezone is missing, then the Dashboard shall flag hour and day views as unverified.
- **FPA-143** The generator shall render the figures quoted in the README and summary documents (interactions, projects, cost, date range) from the JSON, or a `--check-docs` mode shall fail when any quoted figure differs from the JSON.
- **FPA-144** The generator shall number figures and tables sequentially and automatically, with no duplicates.
- **FPA-145** The documentation shall describe the rendering method actually used (inline SVG, no external chart library).
- **FPA-146** The Dashboard shall not render empty placeholders (for example a visitor counter with no value). Where decorative elements are retained, the period label (for example "quarterly results") shall be derived from the data period.

## 14. UX, navigation, and calls to action

### Information architecture

- **FPA-150** The Dashboard shall organize content into five views in this order: Summary, Cost, Breakdown, Habits, Outlook, followed by a Data & method section.
- **FPA-151** The Dashboard shall head each view with the question it answers: Summary ("What is the state of things?"), Cost ("What am I spending?"), Breakdown ("Where does it go?"), Habits ("How do I work?"), Outlook ("What's next?").
- **FPA-152** While the viewport is narrower than 600 px, the Dashboard shall show one view at a time, switched by tabs or a segmented control. While the viewport is 600 px or wider, the Dashboard shall show all views in sequence with in-page navigation.
- **FPA-153** The Dashboard shall provide a single period selector, fixed at the top of the page, that applies to every view.
- **FPA-154** The first viewport shall contain the title, the period selector, and the first headline figure, and no decorative element shall push them below the fold.
- **FPA-155** The Dashboard shall show the top five rows of any ranked list or table by default and offer a "Show all" control to expand it.
- **FPA-156** The Dashboard shall merge related visuals: cost by tool and cash cost in one chart, skills and commands in one toggled view, and the session-length distribution and longest sessions in one view.
- **FPA-157** The Dashboard shall show the Data & method section (definitions, tool timeline, provenance, downloads) collapsed by default.
- **FPA-158** The Dashboard shall not show a separate top-N project chart that duplicates the Portfolio tree (FPA-020) and the Pareto view (FPA-028).

### Headings and copy

- **FPA-160** The Dashboard shall title each chart and table with its finding, generated from the data (for example, "May drove 70% of interactions"), with the descriptive label as a subtitle.
- **FPA-161** The generator shall compute each finding title from a named value and threshold (see FPA-009). If the value is unavailable, then the generator shall fall back to the descriptive label.
- **FPA-162** The Dashboard shall use a single configured language for all interface and generated text.

### Calls to action

- **FPA-165** The Dashboard shall show, at the end of the Summary view, one primary CTA ("Read the series") and up to three secondary CTAs ("Explore the Gantt," "Download the data," "Run it on your logs").
- **FPA-166** The Dashboard shall show no more than one primary CTA per view.
- **FPA-167** The Dashboard shall give each alert exactly one action button that links to the relevant target: the plan settings, the project repository, or the budget input.
- **FPA-168** The Dashboard shall read CTA targets from configuration, and the generator shall fail if a configured target is empty.
- **FPA-169** The Dashboard shall provide "Export CSV" on every table and "Download SVG" on every chart.
- **FPA-170** The Dashboard shall provide a "Share view" control that copies a URL encoding the selected period, view, and tree expansion. When the page loads with those parameters, the Dashboard shall restore that state.
- **FPA-171** If a shared URL contains invalid parameters, then the Dashboard shall ignore them and load the defaults.
- **FPA-172** The Dashboard shall write CTA labels verb-first and no longer than four words.

### Mobile interaction and accessibility

- **FPA-175** The Dashboard shall make every chart inspectable by tap, keyboard focus, and hover, showing the value in a persistent readout. Captions shall not rely on hover.
- **FPA-176** The Dashboard shall size touch targets at least 44 × 44 px.
- **FPA-177** While the viewport is narrower than 600 px, the Dashboard shall keep the first column of wide tables fixed while the rest scrolls horizontally.
- **FPA-178** Where decorative retro elements are retained, the Dashboard shall confine them to the header and footer, make them optional by configuration, disable animation under `prefers-reduced-motion`, and keep text contrast at 4.5:1 or higher.
- **FPA-179** The Dashboard shall include a "skip to content" link and set the document language.

## 15. Verification

- **FPA-100** The test suite shall include a golden test of the aggregations against a fixed JSON fixture.
- **FPA-101** The test suite shall verify tree roll-up sums (FPA-025) and the bridge identity (FPA-065).
- **FPA-102** The test suite shall verify partial-month handling: FME, budget pro-rating, and daily-rate comparisons.
- **FPA-103** The smoke test shall load the generated HTML in Chromium and fail on any console error.
- **FPA-104** The generator shall produce identical output for identical input, aside from the generation timestamp.
- **FPA-105** The test suite shall include golden tests for utilization, break-even, and the plan comparison (FPA-130 to FPA-132).
- **FPA-106** The test suite shall fail if the generated HTML contains duplicate figure or table numbers.
- **FPA-107** The CI pipeline shall run the documentation consistency check (FPA-143) and fail on any mismatch.
- **FPA-108** The smoke test shall fail if the executive summary is empty or any placeholder element has no value.
- **FPA-109** The smoke test shall load the page at 390 × 844 px and fail if the first viewport lacks the title, the period selector, or the first headline figure, or if the page scrolls horizontally.
- **FPA-149** The test suite shall fail if any view has more than one primary CTA, if any CTA target is empty, or if a shared URL does not restore the selected period, view, and tree expansion.
